Model architectures

Architecture 1 · 1980s

Multilayer perceptron (MLP)

The simplest network: layers of neurons where every neuron connects to every neuron in the next layer. Each neuron adds up its weighted inputs and passes the result through a simple non-linear function.

Try it: set the inputs and watch the signal flow
Good at

Fixed-size inputs like table rows. It's also a building block: every transformer layer contains one.

Weak at

No sense of order or space. Shuffle the inputs and it can't tell.

Safety angle

Transformer MLP layers seem to store facts. Their neurons are polysemantic, which is why SAEs were invented.

Architecture 2 · 1998, then 2012

Convolutional neural network (CNN)

Built for images. Instead of connecting to every pixel, a small filter slides across the image looking for one local pattern, like an edge. Stacked layers combine edges into shapes, and shapes into objects.

Good at

Images and video. The same filter works anywhere in the picture, so it needs few parameters.

Weak at

Long-range relationships, like two things on opposite sides of an image. Vision transformers now often win.

Safety angle

Early interpretability work (feature visualisation, "curve detectors") was done on CNNs, and those ideas carried over to transformers.

Architecture 3 · LSTM 1997

Recurrent neural network (RNN)

Reads a sequence one word at a time, carrying a fixed-size "hidden state" from step to step like a running memory. LSTMs added gates to help it remember longer.

Try it: feed words in one at a time
How much of each word is still in the memory

Good at

Streams of data, with constant memory per step: it doesn't grow with length.

Weak at

Early words fade (vanishing gradients), and it can't be trained in parallel because each step waits for the last. Transformers fixed both.

Safety angle

Mostly historical for language, but the idea of a compressed running state is back in state-space models.

Architecture 4 · 2017

Transformers: three flavours

Transformers drop recurrence and let every token attend to others directly, all in parallel. What differs between the flavours is which tokens are allowed to see which, set by the attention mask. (The How transformers work tab walks through one in detail.)

Try it: pick a flavour and a word to see what it can attend to

Rows = token looking, columns = token being looked at. Click a row.

Decoder-only

Each token sees only the past. Trained to predict the next token, so it can generate. Almost all chatbots.

Encoder-only

Every token sees the whole text in both directions. Great for understanding and classifying, e.g. the ModernBERT filter in Deep Ignorance, but it can't generate fluently.

Encoder–decoder

One half reads the full input, the other writes output while looking back at it (cross-attention). The original 2017 design, built for translation.

Variant · 2017 onward, popular since ~2023

Mixture of experts (MoE)

A transformer where each MLP layer is split into many "expert" MLPs. A small router picks the top few experts for each token, so the model can be huge while only a small slice runs per token. Mixtral, for example, uses 2 of 8 experts.

Try it: click a token to see which experts the router picks

Good at

More knowledge for the same compute per token. Cheaper to run than a dense model of the same size.

Weak at

Needs lots of memory (every expert must be loaded) and careful balancing so the router doesn't overuse a few experts.

Safety angle

Experts tend to specialise, often by surface patterns like code or punctuation rather than neat topics. Routing adds another thing to interpret.

Architecture 5 · Mamba, 2023

State-space models

A modern return to the RNN idea: a fixed-size state updated token by token, but designed to train in parallel and remember well. The appeal is cost. Attention compares every token with every other, so cost grows with length squared; a state-space model grows linearly.

Good at

Very long inputs like audio, DNA or whole books, at lower cost.

Weak at

Exact recall of something from far back, since everything is squeezed into a fixed state. Hybrids mix in some attention layers to fix this.

Safety angle

Most interpretability tools were built for transformers. New architectures may need new tools, an open research area.

Method · 2020

Diffusion models

Mostly used for images, video and audio. Training takes real images, adds noise step by step, and teaches a network (often a U-Net or transformer) to predict and remove the noise. To generate, start from pure static and denoise repeatedly.

Try it: drag from pure noise to a finished image

Good at

High-quality images, video and audio, steered by a text prompt.

Weak at

Slow (many steps), and less natural for text, though diffusion language models are being explored.

Safety angle

Deepfakes and non-consensual imagery. Mitigations include training-data filtering, prompt classifiers and watermarking.
